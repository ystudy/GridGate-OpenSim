## Found while checking

- **Gloebit's module starts enabled unless a `[Gloebit]` section says otherwise** (`m_enabled = true`). Outside Gloebit mode GridGate wrote no `[Gloebit]` section, so a `Gloebit.dll` still in the runtime would have run beside the money module. That can happen: leaving Gloebit mode, the launcher couldn't delete the DLL a running region held ("couldn't be removed yet (UnauthorizedAccessException); it will be on the next world start"). It was gone after the world restart, but a grid with several programs could restart one while another holds the DLL. Fixed in `069f5ce6`: outside Gloebit mode every region INI says `[Gloebit] Enabled=false`.
- **Gloebit reads `economymodule` case-sensitively.** GridGate's `[Economy]` key is spelled `EconomyModule`, so Gloebit only "defaulted to Gloebit since dll is present". Fixed in `069f5ce6`: Gloebit mode also sets `[Startup] economymodule = Gloebit`.
- **The Money page forgot the chosen mode** after refusing a switch without the tick. Fixed in `069f5ce6`.
- **A Region Server's Money page talked about pairing** when its grid runs Gloebit. Fixed in `069f5ce6`.
- **Firestorm buys G$ from the region, not from GridGate's economy helper.** Gloebit's module gives the viewer the region's own address as `currency-base-uri`. The helper's Gloebit answers (Task 3) still serve viewers that don't read it.
- **The refusing state's wording** (R1's log and the viewer) says the Region Server "isn't paired" when what's missing is its Gloebit app. Left as is.
- **Gloebit's sandbox is a dead end.** The Gloebit form offers "Sandbox (test payments)" first, and Gloebit's site link follows the app's environment. For the owner to decide: make production the default, or drop the sandbox choice.
- **A Region Server's residents authorize Gloebit again on it.** Gloebit keeps its tables in each program's own database; its page suggests one shared Gloebit database. Known limit.
